# 📊 EshrafProgramManager — برنامج متابعة إرسال المشرفين

تطبيق ويب (RTL، عربي) لمتابعة **من أرسل البرنامج الأسبوعي (تخطيط/فعلي) ومن لم يرسل**، مع تنبيهات SMS، تقارير، تصدير Excel/CSV، و**ترحيل منظم من ردود الاستمارة إلى الأرشيف النهائي** (معاينة ← تأكيد ← إضافة ← تحقق ← حذف الصفوف المُرحّلة من الردود ← أسبوع جديد) مع سجل مهيكل.

> البيانات تُقرأ مباشرة من Google Sheets الحقيقية (CSV) — بلا خادم خلفي وبلا مفاتيح سرية في المستودع.

| **التفاصيل** | برنامج كل مشرف **بمن/إلى تاريخ** + فلتر **نوع البرنامج** + **جدول مقارنة تخطيط ⇦ فعلي** مع شارات ⚠ مختلف / ✓ مطابق |
| **🔗 المقارنة** | مطابقة القائمة المرجعية مع الردود **بمفتاح الاسم فقط** (`Supervisor matching key = Supervisor Name`) + تحذير §6 للمشرفين غير المطابقين |
| **تنبيه SMS** | **إرسال مباشر من الخادم** بلا فتح أي تطبيق: اختيار المشرفين ← مؤشر «تم اختيار N مشرفين» ← مربع النص (أحرف/مقاطع) ← **تأكيد إرسال الرسائل** ← **تأكيد وإرسال** ← `POST /api/sms/send` ← **تقدّم حي** (تم إرسال X من Y) ← **نتيجة: إجمالي/تم/فشل + سبب كل فشل** ← **إعادة إرسال الفاشلة فقط** — **Idempotency-Key** يمنع تكرار الإرسال + **Message ID** + **سجل إرسال الرسائل** |
| **↩ التراجع عن الترحيل** | زر **`↩ التراجع عن آخر ترحيل`** يعيد السجلات المرحّلة **بالضبط** إلى ملف الردود (بترويسة الأسبوع المناسبة) ثم يحذف **سجلات تلك العملية فقط** من الأرشيف ← **تحقق 100% للمفاتيح قبل وبعد** ← يُثبّت الحالة **`REVERSED`** في سجل الترحيل — أي تحقق ناقص **يوقف العملية قبل حذف أي شيء** (نص حرفى §10) |
| **📦 الترحيل** | **مسار الكتابة والقراءة الوحيد**: معاينة (أسبوع حالي ← أسبوع تالي +7، جديد/مكرر/يتيمة + ترويسة) ← **تأكيد الترحيل والحذف/إلغاء** ← إضافة بتنسيق الردود (17 عموداً) ← **تحقق بإعادة قراءة الأرشيف** ← **حذف الصفوف المُرحّلة من الردود فقط** ← تحقق من الحذف ← **أسبوع جديد + سجل مهيكل (6 أعمدة)** |
| **التقارير** | فلاتر (أسبوع/مشرف/مدرسة/نوع/حالة/تاريخ) + تصدير Excel (6 أوراق تشمل **المرحّل**) + CSV + زر الانتقال لشاشة الترحيل — **بلا تقسيم صفوف التفاصيل** |
| **🩺 فحص سلامة البيانات** | شاشة تشخيص: آخر تحديث + حالة المصادر + إحصاءات الردود (إجمالي/مميز/تخطيط/فعلي/غائب/مستبعد/يتيم/مبكر) + **مقارنة المصدر مع الموقع بقراءة طازجة والفرق بالأرقام** + **عرض الردود المفقودة مع سبب كل صف** + جدول أسبوعي كامل بلا تقسيم |
| **الإعدادات** | ربط Apps Script،5 قوالب رسائل، استيراد CSV هواتف، رمز PIN، **سجل العمليات** (العملية/الأسبوع/العدد/التاريخ/المستخدم/الحالة + زر التفاصيل) |
| **🎨 أيقونة التطبيق** | أيقونات داخلية في `assets/icons/` (16–512 + maskable + favicon.ico + SVG) + `manifest.webmanifest` — يظهر رمز البرنامج على الهاتف بعد «إضافة إلى الشاشة الرئيسية» |

### 🔗 فصل المصادر الثلاثة (قاعدة صارمة)

| المصدر | الرابط | الاستخدام |
|---|---|---|
| **الأرشيف النهائي** (Link1) | `1rthlma…` | قراءة للاستعلام التاريخي + **إضافة فقط** أثناء الترحيل — لا حذف/لا تعديل |
| **البيانات المرجعية** (Link2) | `1P2X7VK…` | المدارس/الفعاليات/قائمة المشرفيين (**id عمود الهاتف `phone`**) — **قراءة فقط مطلقاً** |
| **ردود الاستمارة** (Link3) | `16Sw_4Tj…` | الردود الحيّة — تُقرأ وقت الترحيل، **لا يُحذف منها إلا الصفوف التي تحقّق ترحيلها فعلياً** (بترويسة محفوظة) |

الروابط الثلاثة معرّفة بثوابت معلّقة في `js/config.js` (`ARCHIVE_SHEET_URL` / `RESPONSES_SHEET_URL` / `MASTER_DATA_SHEET_URL`).
قائمة المتابعة تأتي **من الملف المرجعي فقط** (31 مشرفاً) — السجلات الخارجة عنها (3 أسماء حالياً) **تُعلَّم ولا تُحذف**.
**مفتاح المطابقة: الاسم فقط** (`phone` لا يدخل المطابقة إطلاقاً) — `[week, name, type, days]` هو مفتاح منع التكرار عند العميل والسكربت معاً.

### 📅 قاعدة إسناد الأسبوع (§7 — سبب جذر العدّ السابق)

الأسبوع يُنسب **من تاريخ الرد لا من ترتيب الصف**: الأسبوع المعلن في ترويسة الاستمارة هو أسبوع النموذج، وردود **الجمعة/السبت قبل بداية الأحد** إرسال مبكر (نافذة يومين) تُنسب إلى أسبوع الترويسة؛ وما هو أقدم من نافذة الإرسال المبكر (لم يُرحَّل بعد) يبقى في أسبوع طابعه الزمني. هذا أزال الفارق القديم (18 صفاً كانت تُنسب للأسبوع السابق فتختفي من شاشة الأسبوع الحالي). الترحيل يكتب **وسم قسم** (`اسم المشرف` + تسمية الأسبوع) قبل صفوف كل دفعة ليبقى الإسناد متطابقاً عند إعادة قراءة الأرشيف.

## 🔗 ربط Google Sheets

### القراءة (جاهز مباشرة)
الروابط الثلاثة معرّفة في `js/config.js` بثوابت معلّقة (`ARCHIVE_SHEET_URL` / `RESPONSES_SHEET_URL` / `MASTER_DATA_SHEET_URL`) بصيغة `/export?format=csv` (للقراءة فقط). إن تغيّرت الروابط، حدّثها هناك فقط.

### الكتابة (خطوة يدوية واحدة)
رابط CSV للقراءة فقط، لذا الكتابة تمر عبر **Google Apps Script** — ومسارها الوحيد شاشة **📦 الترحيل**:

1. افتح [جدول الأرشيف](https://docs.google.com/spreadsheets/d/1rthlmaZES8c95kUI6ErfD4YgiymWq4RoKXNXqgoBPnI/edit) ← الإضافات (Extensions) ← **Apps Script**.
2. احذف المحتوى والصق ملف `apps-script/AppendRows.gs` كاملاً ← احفظ.
3. **Deploy ← New deployment ← Web app**:
   - Execute as: **Me**
   - Who has access: **Anyone**
4. انسخ الرابط المنتهي بـ `/exec` والصقه في: **الإعدادات ← ربط الكتابة**.
5. جرّب من **📦 الترحيل**: معاينة (الأسبوع الحالي ← **الأسبوع التالي +7 أيام**، سجلات جديدة/مكررة/يتيمة + حالة الترويسة) ← زر **✅ تأكيد الترحيل والحذف** (أو **إلغاء**) ← يُضاف إلى الأرشيف بتنسيق الردود (17 عموداً) ← **يُعاد قراءة الأرشيف والتأكد من كل مفتاح وعدد الصفوف** ← ثم تُحذف **تلك الصفوف بالضبط** من الردود (بمطابقة الطابع الزمني + الاسم) ← **يُعاد قراءة الردود للتأكد من الحذف وترويسة محفوظة** ← يُعرض الأسبوع الجديد (+7) وسجل مهيكل (أُضيف · تحقق · حذف · حالة · مستخدم).

> **قاعدة الأمان:** أي فشل (قراءة/كتابة/تحقق/حذف) **يوقف الدورة فوراً وتبقى بيانات الردود كما هي** — لا يُحذف شيء قبل إثبات نجاح الإضافة، ويبقى في السجل «جزئي» مع زر **🔁 إعادة محاولة الحذف**.
> المكرر يُمنع على مستويين: عند العميل (`[week, name, type, days]`) وفي السكربت (مفتاح مماثل بمعالجة عربية مطابقة). الترويسة تُكتب مرة واحدة فقط عند إفراغ الملف (بترتيب أعمدة الردود) — لا رؤوس أسابيع. اليتيمة لا تُرحَّل إلا بخيار صريح في المعاينة. زر التقارير «الانتقال إلى شاشة الترحيل» يقود لنفس المسار (لا يوجد مسار كتابة ثانٍ).

## 📱 إرسال SMS مباشر (Server-side Gateway)

**الإرسال مباشر من النظام**: لا يُفتح تطبيق الرسائل ولا واتساب ولا أي تطبيق خارجي، ولا يُطلب من المستخدم الضغط على إرسال ثانياً.

```text
اختيار المشرفين ← كتابة الرسالة ← 📱 إرسال SMS ← تأكيد إرسال الرسائل
   ← «تأكيد وإرسال» ← POST /api/sms/send (خادمك) ← SMS Provider API ← نتيجة كل مشرف
```

### التشغيل (خطوة واحدة — الأسرار في البيئة فقط)

```bash
cp .env.example .env          # املأ SMS_UPSTREAM_URL و Token/Key داخل .env (مُضيف إلى .gitignore)
node serve.mjs                # يشغّل الواجهة + بوابة الإرسال معاً
```

| المتغير | الغرض |
|---|---|
| `SMS_UPSTREAM_URL` | رابط إرسال مزوّدك (يستقبل POST JSON: `{to, message, text, from, idempotencyKey}`) |
| `SMS_API_TOKEN` / `SMS_API_KEY` / `SMS_API_USER`+`SMS_API_PASSWORD` | توثيق المزوّد — يُرسل من الخادم فقط |
| `SMS_FROM` · `SMS_TIMEOUT_MS` | المرسل · مهلة الاتصال |

- **البوابة:** `POST /api/sms/send` (مفرد) · `POST /api/sms/bulk` (عدة مستلمين) · `GET /api/sms/health` — كلها JSON، والأسرار لا تظهر في المتصفح ولا في المستودع أبداً.
- **من المتصفح:** `SmsService.sendSms(phone, message)` و `sendBulkSms(recipients, message)` عبر `/api/sms/send` (قابل للتغيير من الإعدادات).
- **التدفّق داخل التطبيق:** اختيار (واحد/عدة/الكل/بحث) ← مؤشر **تم اختيار N مشرفين** ← مربع النص + **عدد الأحرف** و**عدد الرسائل المتوقعة** ← تأكيد (**إلغاء / تأكيد وإرسال**) ← شريط تقدم **جاري إرسال الرسائل... (تم إرسال X من Y)** ← نتيجة (**إجمالي الرسائل / تم الإرسال بنجاح / فشل الإرسال** + سبب كل فشل باسم المشرف) ← **سجل إرسال الرسائل**.
- **منع التكرار:** تعطيل الزر أثناء الإرسال + `Idempotency-Key` لكل رسالة (يحفظه الخادم 10 دقائق فلا يُستدعى المزوّد مرتين بنفس المفتاح).
- **الفشل الجزئي لا يوقف الكلي**؛ بعد الانتهاء زر **إعادة إرسال الرسائل الفاشلة** (لا تُعاد الناجحة أبداً).
- **الحالات:** `SENT` / `PENDING` / `FAILED` — ولا يُدعى وصول الرسالة إلا إن أفاد المزوّد بذلك (**تم إرسال الطلب إلى مزود الرسائل**).
- الأرقام: من الأرشيف/الاستيراد بالاسم فقط — لا يُستخدم رقم الهوية أبداً؛ من دون رقم: `الاسم — لا يوجد رقم جوال صالح` بلا إرسال.
- أدوات يدوية منفصلة (فتح تطبيق الرسائل/واتساب) موجودة كأزرار صريحة **خارج** مسار الإرسال المباشر.
- الاستضافة الثابتة (GitHub Pages) لا تشغّل الخادم: اشغّل `node serve.mjs` على جهازك/خادمك ووجّه حقل بوابة الإعدادات إليه.
- **مسار أندرويد موازٍ:** نسخة `.aia` تُرسل **مباشرًة من شريحة الهاتف** (`Texting.SendMessageDirect` + صلاحية `SEND_SMS`) بلا خادم — انظر قسم «نسخة App Inventor» أدناه.
- لإدخال الأرقام: **الإعدادات ← استيراد CSV هواتف** (عمودان: الاسم/الرقم).

## 📱 نسخة App Inventor (`.aia`) — إرسال مباشر من الشريحة

`EshrafProgramManager.aia` — نسخة أندرويد مبنية من كتل مُتحقًّا من مصادر AI2 الرسمية (**769 كتلة، 17 مكوّناً، YaVersion 237**)، ويكمل مسار **الإرسال المباشر من شريحة الهاتف (SIM)**:

```text
اختيار مشرف (أو 📨 إرسال للظاهرين) ← تأكيد «تأكيد وإرسال / إلغاء»
   ← طلب صلاحية SEND_SMS وقت التشغيل ← (منح) ← Texting.SendMessageDirect
   ← SmsManager ← الشريحة ← رسالة SMS حقيقية بلا فتح تطبيق المراسلة
   ← سجل بختم وقت + ملخص (إجمالي/تم/فشل) + إعادة إرسال الفاشلة فقط
```

**ما تفعله النسخة:**
- تجلب عند فتح الشاشة ملفي CSV الحقيقيين (المشرفون + الردود الحيّة) عبر مكوّن Web.
- تعرض قائمة الحالة لكل مشرف: 🟢 أرسل الاثنين · 🟠 تخطيط فقط · 🔵 فعلي فقط · 🔴 لم يرسل.
- إحصاءات في أعلى الشاشة: الإجمالي/تخطيط/فعلي/لم يرسلوا · بحث بالاسم.
- **عند اختيار مشرف:** تُحضّر الرسالة فقط (لا إرسال تلقائي) — الإرسال بزر **`📱 إرسال SMS`** بعد التأكيد.
- **زر `📨 إرسال للظاهرين`:** دفعة واحدة للمحدَّدين مع **تقدّم حيّ** (جاري الإرسال... k من N) عبر مؤقّت — مشرف واحد في كل نبضة.
- **الصلاحية:** يُطلب `android.permission.SEND_SMS` وقت التشغيل؛ عند الرفض يظهر نص §3 حرفياً (`لم يتم منح صلاحية إرسال الرسائل النصية...`).
- **السجل:** `الاسم — الرقم — الوقت — PENDING/FAILED` بتنسيق `FormatDateTime` داخل `lstLog`، ثم ملخص `إجمالي المشرفين / تم الإرسال / فشل`، ومع الفشل فقط زر `إعادة إرسال الرسائل الفاشلة`.
- تنظيف الرقم (فراغ/شرطة) على نسخة الإرسال فقط، والتحقق `8–15 خانة`؛ لا يُستخدم رقم الهوية إطلاقاً.

**المكوّنات:** `lblTitle`, `lblStatus`, `txtSearch`, `hrBtns` (`btnSearch`,`btnRefresh`), `lstStatus`, `hrSend` (`btnSend`,`btnAll`), `lblLogT`, `lstLog`, `webLists`, `webPrograms`, `notifier1`, `txt1` (Texting v5), `clock1` (Clock v4).

**حدود صريحة (بلا ادّعاء):**
- **ذوو شريحتين (Dual SIM):** غير متاح — مكوّن Texting الرسمي لا يخصّص شريحة، الإرسال من الشريحة الافتراضية.
- **تقرير التسليم (DELIVERED):** غير متاح بلا امتداد (extension)؛ المعروض إشعار الـ SENT المدمج في Texting.
- **الأرقام المعروضة في جدول الاختبار (جهاز حقيقي/شريحة/Send_SMS/عربي/طويل/فشل): لم تُنفَّذ هنا** — لا يوجد جهاز في بيئة البناء؛ الاختبار اليدوي المطلوب في الأسفل.
- لا كتابة في Sheets · لا JavaScript داخل التطبيق · إعادة بناء القائمة عند كل بحث.

**الاختبار اليدوي المطلوب على هاتف حقيقي (قبل الادّعاء بأي PASS):**
1. استورد الـ `.aia` وابنِ APK من AI2 (الـ Companion قد لا يرسل مباشرة من الشريحة).
2. اختر مشرفاً ← `📱 إرسال SMS` ← تأكيد ← اقبل الصلاحية ← تحقق وصول SMS فعلي.
3. ارفض الصلاحية ← تأكيد نص الرفض §3 حرفياً.
4. `📨 إرسال للظاهرين` مع ≥3 ← تقدّم k من N ← سجل بختم وقت ← ملخص.
5. رقم ناقص/فارغ ← `لا يوجد رقم جوال صالح` بلا إرسال.

الاستيراد: App Inventor ← Projects ← **Import project (.aia) from my computer** ← اختر الملف ← اضغط **Connect → AI Companion** للتجربة (والبناء APK عبر **Build → App (.apk)**).

## ⚠️ قيود صريحة

1. **القراءة** من Sheets تعمل بلا إعداد؛ **الكتابة** تتطلب نشر Apps Script (أعلاه).
2. لا أرقام هواتف في أي مصدر حالي — استورد CSV هواتف أو استخدم مزوّد API.
3. **الإرسال الصامت من SIM** متاح في نسخة App Inventor (أندرويد، مع صلاحية `SEND_SMS`) فقط — المتصفح لا يملك صلاحية إرسال SMS؛ أدوات «فتح تطبيق الرسائل/واتساب» اليدوية تفتح محرّراً جاهزاً وليست إرسالاً صامتاً.
4. لا توجد خطوة بناء ولا اعتماديات npm — كل شيء ثابت وقابل للنشر المباشر (build APK للنسخة الأندرويد يتم داخل AI2).
